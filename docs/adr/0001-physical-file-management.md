# 1. 坚持物理文件管理模式与离线自治架构

## 上下文与问题陈述
在设计模组管理器（UMM）的方案隔离与插件启停机制时，存在两种架构路线：
1. 基于 WinFsp / Dokan / Overlay 的虚拟文件系统（VFS）；
2. 基于物理目录管理与 `.dll` / `.dll.disabled` 改名的真实文件系统方案。

## 决策
我们决定**彻底拒绝虚拟文件系统（VFS），全面采用 100% 物理文件管理与离线自治优先架构**。

## 理由与权衡
- **Unity Mono 与底层引擎兼容性**：Unturned 底层的 Mono 运行时、Steam 校验以及 BattlEye 反作弊扫描对虚拟盘路径（如符号链接、挂载驱动器）存在不可控的崩溃与访问冲突。
- **离线自治与稳定性**：物理改名（将 `.dll` 改为 `.dll.disabled`）和独立物理 profile 目录（`profiles/<Id>/`）不依赖任何第三方驱动，即便启动器未启动或离线断网，游戏也能稳定加载已配置的环境。
- **可逆性与排障便利**：玩家可以直接在 Windows 资源管理器中直观看到插件物理状态，降低了排障认知负担。
