# 4. Windows 原生文件关联与安全导入审查向导规范

## 上下文与问题陈述
随着 `.ummpk` 模组包与 `.ummtheme` 主题包成为玩家分享与生态分发的核心载体，用户期望在 Windows 资源管理器中双击直接调起启动器。
然而，外部双击传参面临多重工程与安全挑战：
1. **静默解压的巨大安全风险**：若双击直接在后台解压，可能在用户不知情的情况下覆盖玩家精心微调的 `.cfg` 键位或引入未预期的插件；
2. **并发与单实例状态竞争**：短时间内多次双击或在首次启动向导（`OnboardingWindow`）未完成时传参，极易引发 WPF 模态对话框死锁或并发文件写入冲突；
3. **注册表污染与便携性考量**：便携式使用场景（`AppDataPaths.IsIsolatedProfile`）不应无脑篡改用户系统的文件关联。

## 决策
我们决定实施**Windows 原生文件类型自愈注册、单实例 FIFO 队列调度与显式安全审查向导架构**。

## 核心规约
1. **注册表生命周期**：
   - 启动器常规运行（非便携隔离模式）时自动在 `HKCU\Software\Classes` 注册与自愈 `.ummpk` 与 `.ummtheme` 的打开方式、ProgID 与图标；
   - 在“设置-高级/系统”页提供“修复关联”与“解除关联”显式控制按钮，尊重便携用户的系统纯净性；
   - 便携调试模式下绝对静默，不修改注册表。
2. **零静默解压与显式审查向导（Explicit Preview Modal）**：
   - 双击文件唤醒主实例置顶，先经过沙箱预检，随后弹出阻断性模态向导；
   - 向导展示包含的插件/主题元数据、目标文件清单，并醒目标注版本变更与同名冲突；
   - 只有用户在界面上明确点击“确认导入”后，才开始执行物理文件写入。
3. **多 Profile 解析与冲突保护**：
   - 默认安装至当前“活跃 Profile”，但在向导中允许下拉切换至其他 Profile 或选择“以此包新建独立方案”；
   - 冲突处理：被覆盖的同名 `.dll` 自动备份为 `.bak`；同名配置文件（`.cfg`）默认勾选“保留本地配置”，避免玩家键位配置被覆盖冲掉。
4. **主题包即时生效语义**：
   - 导入 `.ummtheme` 提供“立即应用此主题”选项（默认勾选），确认后解压并热应用；若取消勾选则仅持久化至本地主题库。
5. **单实例 FIFO 队列与状态守护**：
   - `SingleInstanceService` 接收到的外部激活参数进入线程安全队列（FIFO），受单一模态守护（Single Modal Guard）保护，依序展示，杜绝弹窗重叠；
   - 若传入时处于首启动向导状态，暂存队列待主窗口完成加载后再依序激活。
6. **沙箱违规红牌阻断**：
   - 若检测到危险扩展名（如 `.exe` / `.bat` / `.ps1`）、路径穿越（`..`）或 Zip 炸弹，立即阻断，不提供“继续”按钮，弹出红色警示并提供日志诊断。
