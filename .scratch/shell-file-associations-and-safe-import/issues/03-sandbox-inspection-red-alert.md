# 03: 沙箱违规拦截红牌告警与安全预检

**What to build:** 在任何外部 `.ummpk` 或 `.ummtheme` 导入前，启动器执行不可绕过的多层沙箱预检。若发现危险可执行脚本（`.exe`、`.bat`、`.cmd`、`.ps1`、`.vbs` 等）、路径穿越攻击（`..` 目录逃逸）、解压条目超限（>4096）或解压体积超限（>1GB），立即强行终止导入流程，不提供“继续导入”按钮，弹出醒目的红色安全警示对话框，展示违规条目明细与拦截规则原因，并支持一键复制诊断信息，彻底阻断恶意文件危害。

**Blocked by:** 02: 启动传参与单实例安全队列分发

**Status:** resolved

- [x] 实现针对 `.ummpk` 与 `.ummtheme` 的压缩包多层沙箱安全预检服务
- [x] 严格拦截危险扩展名、路径穿越、Zip 炸弹与非法目标路径
- [x] 弹出专用的红色警示对话框，列出被拦截的文件明细与违规规则，不提供导入操作
- [x] 提供一键复制违规排障信息功能
- [x] 包含针对恶意构造 Zip（含脚本、含穿越路径、含虚假扩展名）的沙箱自动化单元测试

## Answer
已通过 TDD 循环完成 Ticket 03 的全部交付：
1. 实现了 `PackageSandboxInspectionService`，严格校验解压条目数（<=4096）、解压体积（<=1GB 或主题 <=50MB）、路径穿越跳脱符（`..`、盘符、空字节），以及全套系统脚本可执行文件黑名单，且主题包中严禁出现任何可执行脚本与 `.dll` 二进制载荷；
2. 实现了 `SandboxInspectionResult` 与 `SandboxViolation` 数据结构，提供格式化的诊断排障文本生成器 `FormatDiagnosticReport()`；
3. 构建了专用的红色警示对话框 `SandboxAlertWindow`（WPF-UI 规范设计），列出拦截的违规条目路径、规则名称与违规详情，提供一键复制排障诊断信息至剪贴板，彻底不提供任何“继续导入”按钮，强行终止恶意导入流程；
4. 在 `MainWindow.HandleShellFileIntent` 中强行挂载沙箱预检门禁；
5. 在 `SandboxInspectionTests.cs` 中编写针对脚本载荷、路径穿越、主题包携带 dll 及合规资产的单元测试，全套测试 107/107 全部绿灯通过。
